# jamlab 小小实验室：儿童知识系列设计提案

状态：2026-11-20 已获用户确认，按本方案实现并发布。本文保留设计阶段的提案措辞与范围；未来题材仍为方向建议。

## 核心定位

一个陪孩子从问题出发、动手验证、逐步理解世界怎样运转的系列。用孩子可以观察和操作的事实，搭出解释；能用自己的话说原因，预测条件改变后的结果，再把原理用到新问题上，是比“看完”更有用的学习证据。

对孩子说：“这个世界，为什么会这样？”

对家长说：“一起动手，把为什么弄明白。从看得见的小现象，走到能解释、能预测、能重新做出来的理解。”

“第一性原理”作为编辑方法与家长说明，不要求孩子先记住术语。不承诺一个系列读完就完全掌握一门科学。

## 使用人群与节奏

当前 Code for Kids 是低龄亲子共读材料；首版据此支持刚识字孩子与成人共读，也允许能独立阅读的孩子自己探索。全系列不标未经验证的统一年龄。各专题按实际内容标识阅读方式、已有经验和阅读负担。

给孩子的主体用大字、短句、直接动作。给家长的说明放在页尾可展开区域。一次可以只做一个小实验；观察、猜想和复述允许口头表达、画图或演示，不要求长篇打字。

## 页面结构与拟用文案

1. **页头**：jamlab / 小小实验室；“开始探索”“怎么学”“给大人”；回 jamlab。
2. **第一屏**：标题“这个世界，为什么会这样？”；正文“从一个小问题开始。猜一猜，动手试，再把里面的道理找出来。”；主要按钮“从手电筒开始”；次要文字链接“看看我们怎么探索”。旁边是手电筒、连线、开关、齿轮、纸桥等组成的探索工作台，标注“一个问题，可以走很远”。目前可进入的物件只有手电筒，其余为插画，不暗示已有课程。
3. **现在可以开始：01《编码》给孩子**。问题标题“小小的开关，怎么变成计算机？”；简介“从一束光传消息，到让电路算数、记事，再画出屏幕上的图。”；展示“25 章互动内容 / 可亲子共读”；主按钮“探索这个系列”指向专题首页，另列“第一站：手电筒能说话吗？”指向第 1 章。
4. **把一个问题追到底**：用现有计算机专题解释路径：如何传消息 → 信号怎样表示意思 → 开关怎样计算和记忆 → 指令怎样让部件协作 → 数字怎样成为文字和图像。这是机制依赖的学习路线，不宣称计算机发明史唯一地按此发生。
5. **我们这样发现**：遇到问题 → 先猜办法 → 动手试验 → 说清原因 → 换个情况再试。移动端为纵向五个简短步骤，每一步有一个真实的手电筒例子。
6. **更多为什么，慢慢打开**：一条开放的未来工作台。可用纸桥、光影、声音的轮廓代表题材空间，但必须标“未来探索方向，尚未开放”，不呈现虚假课程数量、进度或发布日期。
7. **给一起探索的大人**：如何提问、怎样判断理解、简化模型的边界。提供“我发现……因为……如果改成……我猜……”的谈话支架。共读提示：“孩子猜错时，先一起找证据，再修改解释。”
8. **页尾**：回 jamlab；访问《编码》给孩子；“每个大问题，都可以从一个小发现开始。”

## 如何让第一性原理真正体现在内容里

统一的设计单元是“一个需要解释或解决的问题”，而不只是“一个术语”。未来每个专题都要回答：

- 想解释什么现象，或解决什么真实问题？
- 已经能观察到什么？当前实验允许使用什么条件？
- 孩子自己的第一种办法是什么？在哪里遇到限制？
- 改一个条件，会得到什么结果？先预测，再比较。
- 哪个规则能解释这些现象？它的适用条件是什么？
- 能否用同一规则解释新情形，或重新设计一件东西？

科学专题从观察和可重复证据建立、修正模型；工程专题从需求、条件和取舍构造方案。两者都允许多个合理答案。人类发明的约定与自然规律要区分，例如“0/1 的命名”“某个字符的编号”是约定，不能解释为物理必然。

保留已知事实、当前模型的假设和未知之处。儿童化表达可以暂缓深层机制，但不能将比喻当作完整解释，也不要求一节课递归解释到全部物理基础。真实历史中的选择单独说明，不能把便于教学的重建路线当作唯一历史。

## Code for Kids 的完整示例

问题：“你和朋友隔着窗户，听不到说话，怎样用灯光约好一件事？”

1. 观察：朋友能看到灯亮或灯灭；目前只有一盏灯。
2. 猜想：亮一下表示“来玩”，亮两下表示“明天玩”。允许孩子自己约定。
3. 验证：让另一个人按约定解读，观察是否一致。
4. 暴露限制：连续发两条消息，中间没有分隔，接收的人可能不知道如何切开。
5. 构造规则：给出或自己设计分隔办法；比较前后结果。不是宣布“必须用某套标准码”。
6. 抽象：消息需要双方共享的表示与分隔规则；信号本身不会自动带上约定的含义。
7. 迁移：换成敲桌子的声音或纸上的符号，规则还可以用吗？再增加一种消息，原来的规则够不够？

理解的证据：能指出哪条消息有歧义、说出原因、提出一种可被别人正确解读的修改方案。不以背出“编码”的定义、点满按钮或通关次数代替理解。

已核查现有仓库 README 与第 1、10、25 章，包含操作、预测和“问问孩子”等环节；这份提案说明系列级方向，不等于对全部 25 章的科学准确性和教学效果作了完整审定。

## 视觉方向

延续主站暖白纸感、橙色与植物绿。新增少量天蓝用于光与信号。像一张真正能动手的小工作台，使用可辨认的零件、带编号的纸条和手绘箭头；用连接关系表现原因和结果。

主文字深灰，次要文字仍保持对比度；中文优先，英文字母仅作低优先级标记。正文约 18–20 px，交互目标至少 48 px，段落简短、留白充分。移动端正常纵向阅读，不要求拖动才能进入专题，不依赖鼠标悬停或颜色单独传达状态。

插画可以有轻微动效，但变化应解释输入和结果。不开自动声音，不做快速闪烁，尊重减少动画设置。首版视觉稿静态展示，不引入儿童账号、排行榜、连续打卡或自动采集数据。

原理图、按钮状态与关键说明在动画关闭、低性能设备和无 JavaScript 的情况下仍可读。
